# 弹里个弹（games/danli）

回合制抛物线对战：萌宠和厨房道具大乱斗。两队小动物站在悬空的面团地形上，轮流调角度、按住蓄力、看风开炮，把对手打空血量或轰出画本就赢。
设计正本见 [DESIGN.md](DESIGN.md)，模块约定见 [AGENTS.md](AGENTS.md)，更新见 [CHANGELOG.md](CHANGELOG.md)，素材来源见 [ASSETS.md](ASSETS.md)。

现在是 0.2.0：单机，先进准备房间挑对阵（1v1、2v2、3v3，空位由电脑补，电脑可以是队友也可以是对手）、地图（6 张，或"随机"）和武器（8 把），
6 位电脑人物（橘子、团团、企企、柴柴、兔兔、鼠鼠）各拿自己喜欢的武器；常用道具（连发、三岔、加力）和特殊道具（纸飞机、锅盖）；WebAudio 现场合成的音效；
我方真人出局以后能快进或跳到结果；结算页有每个人的伤害、命中、轰出画本。地图、地形、远景、角色、武器图标和页面照美术代理的交付稿（见 ASSETS.md）。
没有好友房、特技、怒气和新手教程。

## 开发

```bash
npm ci
npm run dev        # http://localhost:5179/games/danli/（平台的 /api 转给 5181，没起也能玩，当游客）
npm test           # tsc（页面和 Worker）+ vitest
npm run build:cf   # 打包到 dist-cf/games/danli/（部署用）
npm run smoke      # 无头浏览器：手机横屏、竖屏各走一遍"首页 → 房间（冰淇淋雪山、3v3、换武器和小动物）→ 开打 → 自己出局 → 跳到结果 → 结算"，控制台零报错
npm run shots      # 验收截图：电脑 1280×720、手机竖屏 390×844（首页、房间三张、6 张图各一张、出局、结算），存到 shots/v020-*.png
npm run perf       # 手机性能：CPU 降速 4 倍，量跟随、拖动、跟炮弹的帧
npm run sim 100    # 模拟器：电脑对电脑打 100 局（1v1；加 2v2 / 3v3 换对阵，加 mix 让电脑拿性格武器、room 用房间的默认阵容，
                   #   map:<id> 换地图、map:all 六张各打一遍，cap:N 改打满几轮，ab 比各道具用和不用）
npm run sim 16 weapons  # 8 把武器两两 1v1 对打，每对 16 局，打印胜率表
```

无头浏览器用 playwright-core，浏览器找法见 `scripts/browser.ts`（环境变量 `CHROME`，或 playwright 缓存里的 chrome-headless-shell）。
地址上带 `?seed=数字` 时新开的局用这个种子（复现、截图用）；带 `?turbo` 时动画加速（冒烟用）。页面上有一个只读的 `window.__danli`（看状态、问电脑会怎么打），给冒烟和截图脚本用。

## 规则要点（数值都在代码里一处）

- 世界 3000×780，地形网格每格 4×4（`core/terrain.ts`）；格子存材质，被炸焦的格子打个标记（画坑边用）。悬空的地断开以后不塌落。
- 炮弹：位置、速度以 1/1024 单位存，每帧 `vx += 风 × 6`、`vy += 256`（`core/physics.ts`）；力度 1 点 = 初速度 256，满力 45° 大约打 2500 远。每帧的位移切成不超过 2 单位的小段查碰撞。
- 地图（`core/mapData.ts`，美术交付）：6 张，画本都薄，每块地有材质（材质码写进格子低 7 位，规则上都一样）。
- 出生点：每张图一张候选表（只写 x，至少 10 个：前五张 11 个、早餐吐司桥 10 个；脚下都厚 80 以上），开局用 `open` 洗牌、两队交错挑，离对手至少"地图宽 ÷ (人数 + 1)"、离队友至少 240（`core/rules.ts` 的 `pickSpawns`，算法见 DESIGN.md 第 3 节）；开局朝着最近的对手。
- 武器（`core/weapons.ts`）：8 把，攻、防、爆炸范围、角度照 DESIGN.md 2.6；爆炸范围三档：小（伤害半径 22、挖 19）、中（30、26）、大（40、35），挖坑照包子蒸笼的比例。
  特技还没做。基础伤害是调平用的（设计表里没有）：包子 36、西瓜 31、球拍 39、萝卜 36、烟花 36、拖鞋 68、飞盘 38、奶茶 34，见下面"数值"。
- 爆炸：以命中点为圆心挖圆；直接打中人时圆心放在他身子中间，坑一定挖到他脚下。伤害 = 基础 × (70 + 5 × 攻)/100 × (100 − 3 × 对方防)/100 × 距离衰减（到半径边上一半）× 道具倍率，整数。推开最远 24。
- 体力：每回合 100，爬和道具共用（`core/rules.ts`）。爬一步 4（一格）扣 2，往上每 2 单位高差多 1，一步最多上下 12；前面是空的就停住。
- 血量上限 180（`core/rules.ts` 的 `MAX_HP`）。
- 道具（`core/items.ts`）：发射方式三选一（连发 +1 每发 60%、+2 每发 45%、三岔每颗 50%）、加力三选一（10% / 20% / 50%，花 8 / 18 / 60），可以叠；特殊道具纸飞机、锅盖每局各 2 次。
  连发一颗一颗算（前一颗的坑、掉落会影响后一颗，自己出局了就不再扔）；三岔三颗同时飞、按落地先后炸；每颗都照常挖坑，倍率只乘在伤害上（万分比整数）。
  纸飞机落地不炸、人瞬移到落点上方第一个站得下的地方，撞到人就落在他旁边最近的空位，飞出画本作废；不能和别的道具一起用。
- 掉落：脚下（中间和左右各 3）都没地就往下掉；摔超过 60 每 10 扣 1、最多 20；掉到底边或出了左右边就出局。
- 对阵：两队各 1–3 人（`setupError` 检查），座位顺序就是开局设置里 players 的顺序（蓝队我、队友，再黄队）。
- 出手和轮：两队交替出手、队内按座位轮，出局的跳过；还活着的每个人都出过一次手算一轮（人少的那队一轮里有人出手两次），打满 15 轮按全队剩余血量总和定胜负（`MAX_ROUNDS`；开局设置的 `maxRounds` 只给模拟器用）。
  `turn` 是第几次出手（风和电脑的随机流按它取），`round` 是第几轮，顶栏写"第 N 轮 / 15"。
- 电脑（`ai/index.ts`）：只朝对手那边打；伤到自己扣 1.5 倍、伤到队友扣 2 倍。人物（`ai/personas.ts`）：橘子包子蒸笼、团团奶茶炮、企企弹弹球拍、柴柴西瓜投石器、兔兔冲天烟花筒、鼠鼠萝卜钻（准备房间里电脑座位的默认武器）。
- 准备房间（`room.ts`）：同一只小动物一局只上一次（我和五个电脑座位互不相同，换成在场的那只就对调）。默认阵容两队均衡（各有一把大范围的武器）：
  我（柴柴、西瓜投石器）、橘子（包子蒸笼）、团团（奶茶炮）对兔兔（冲天烟花筒）、鼠鼠（萝卜钻）、企企（弹弹球拍），1v1、2v2 按这个顺序截。
- 我方真人全部出局以后：顶栏下面出"快进 ×4"（动画四倍速，再点恢复）和"跳到结果"（剩下的回合电脑直接算完，每两手让一下页面，然后进结算页）。

## 性能

- 远景整张、地形每 256×256 一块，都是烘焙好的画布，放在"镜头那一层"里按世界坐标摆好；镜头平移缩放只改这一层的 CSS transform（交给合成器），每帧不重贴；
  炸到哪块只重画哪块。上面一张透明画布每帧只画纸边、角色、炮弹、特效和名牌，JS 一帧约 1–2 ms。
- 画布渲染倍数封顶 2（手机按像素比 3 时也按 2 画）；远景按 0.4 倍烘焙。
- 实测（`npm run perf`，无头 Chrome、关 GPU 的软件渲染，手机横屏 844×390）：不降速时跟随、拖动、跟炮弹都是一帧 16.7 ms；
  CPU 降速 4 倍、像素比 3（画布按 2 画）时一帧约 50 ms（p95 约 67 ms），像素比 1.5 时约 33 ms，像素比 1 时中位 16.7 ms；
  每帧 JS 只花 1–2 ms，其余是软件合成整屏透明画布的时间（把上面那张画布或下面那一层任意藏掉一张，降速 4 倍也是 16.7 ms）。真机由 GPU 合成，还要在手机上实测确认。

## 监控

照 docs/platform-backend.md 第 16 节接平台的监控：
- `GET /games/danli/health` 回 `{"ok":true,"version":"<package.json 的 version>"}`（不缓存）：排在 Worker 路由最前面，不过登录闸门、不读存储、不问平台，单独部署也能访问；版本号从 `package.json` 导入，打包时内联；
- `wrangler.jsonc` 开着 `observability`（Workers Logs）；
- 页面入口调一次 kit 的 `reportErrors`（`arcade-kit/report`），没人接住的报错报给平台的 `/api/client-error`：只带报错、调用栈、路径、游戏和版本。

## 部署

`wrangler.jsonc` 是独立配置（只有静态资源 `ASSETS`，没有 Durable Object，不写平台绑定和 `GATE`）：`npm run deploy` 能单独部署成一个游客就能玩的游戏。
本站部署时由维护者的部署工具补平台绑定、`GATE`、路由（见仓库根 docs/new-game.md 第 4、5 节）。还没有接平台的云存档和排行榜。
