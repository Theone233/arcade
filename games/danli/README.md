# 弹里个弹（games/danli）

回合制抛物线对战：萌宠和厨房道具大乱斗。两队小动物站在悬空的面团地形上，轮流调角度、按住蓄力、看风开炮，把对手打空血量或轰出画本就赢。
设计正本见 [DESIGN.md](DESIGN.md)，模块约定见 [AGENTS.md](AGENTS.md)，更新见 [CHANGELOG.md](CHANGELOG.md)，素材来源见 [ASSETS.md](ASSETS.md)。

现在是第一版 0.1.0：单机 1 对 1 打电脑"橘子"，一张图（厨房面团岛），一把武器（包子蒸笼），常用道具（连发、三岔、加力）和特殊道具（纸飞机、锅盖）。没有好友房、特技、怒气和备战页。

## 开发

```bash
npm ci
npm run dev        # http://localhost:5179/games/danli/（平台的 /api 转给 5181，没起也能玩，当游客）
npm test           # tsc（页面和 Worker）+ vitest
npm run build:cf   # 打包到 dist-cf/games/danli/（部署用）
npm run smoke      # 无头浏览器：手机横屏、竖屏各打完一局，控制台零报错
npm run shots      # 验收截图：电脑 1280×720、手机竖屏 390×844，存到 shots/v010-*.png
npm run perf       # 手机性能：CPU 降速 4 倍，量跟随、拖动、跟炮弹的帧
npm run sim 100    # 模拟器：电脑对电脑打 100 局（加 ab：再比各道具用和不用的胜率）
```

无头浏览器用 playwright-core，浏览器找法见 `scripts/browser.ts`（环境变量 `CHROME`，或 playwright 缓存里的 chrome-headless-shell）。
地址上带 `?seed=数字` 时新开的局用这个种子（复现、截图用）；带 `?turbo` 时动画加速（冒烟用）。页面上有一个只读的 `window.__danli`（看状态、问电脑会怎么打），给冒烟和截图脚本用。

## 结构

```
src/core/      规则核心（纯函数、确定性）：fixed 整数角度表和整数开方、terrain 地形网格、maps 地图数据、physics 炮弹、weapons 武器表、items 道具表、rules 回合和结算
src/ai/        电脑：personas 电脑人物（名字要登记进平台的保留昵称）、index 出手
src/view/      画面：scene 战场（镜头、动画、角度盘、画面外小牌）、terrainArt 地形分块烘焙、backdrop 远景和纸边、chars 角色和名牌、hud 对局界面（道具栏的按钮和四种状态）、itemIcons 道具图标、lobby 选桌页
src/solo.ts    单机存档（danli.solo：种子 + 开局设置 + 操作序列，读档时重放）
src/main.ts    页面入口：选桌页 → 对局 → 结算
worker/        Worker：独立部署时站点根转到 /games/danli/，首页过 kit 的登录闸门（本站登录、独立部署游客）
test/          vitest：确定性、角度表、地形和挖坑、物理、爬和体力、掉落出局、伤害、道具（体力、组合、次数、倍率、连发、三岔、锅盖、纸飞机）、回合和胜负、电脑、架构约束
scripts/       冒烟、截图、性能、模拟器
```

## 规则要点（数值都在代码里一处）

- 世界 3000×780，地形网格每格 4×4（`core/terrain.ts`）；格子存材质，被炸焦的格子打个标记（画坑边用）。悬空的地断开以后不塌落。
- 炮弹：位置、速度以 1/1024 单位存，每帧 `vx += 风 × 6`、`vy += 256`（`core/physics.ts`）；力度 1 点 = 初速度 256，满力 45° 大约打 2500 远。每帧的位移切成不超过 2 单位的小段查碰撞。
- 地形（`core/maps.ts`）：画本要薄，厨房面团岛主体厚 85–105，山尖下面约 140，左尖、悬崖脚、浮岛更薄；出生点都在 85–100 厚的地方。
- 爆炸：以命中点为圆心挖圆（包子蒸笼挖坑半径 26，伤害半径 30）；直接打中人时圆心放在他身子中间，坑一定挖到他脚下。伤害 = 基础 36 × (70 + 5 × 攻)/100 × (100 − 3 × 对方防)/100 × 距离衰减（到半径边上一半）× 道具倍率，整数（`core/weapons.ts`）。推开最远 24。
- 体力：每回合 100，爬和道具共用（`core/rules.ts`）。爬一步 4（一格）扣 2，往上每 2 单位高差多 1，一步最多上下 12；前面是空的就停住。
- 血量上限 180（`core/rules.ts` 的 `MAX_HP`）。
- 道具（`core/items.ts`）：发射方式三选一（连发 +1 每发 60%、+2 每发 45%、三岔每颗 50%）、加力三选一（10% / 20% / 50%，花 8 / 18 / 60），可以叠；特殊道具纸飞机、锅盖每局各 2 次。
  连发一颗一颗算（前一颗的坑、掉落会影响后一颗，自己出局了就不再扔）；三岔三颗同时飞、按落地先后炸；每颗都照常挖坑，倍率只乘在伤害上（万分比整数）。
  纸飞机落地不炸、人瞬移到落点上方第一个站得下的地方，撞到人就落在他旁边最近的空位，飞出画本作废；不能和别的道具一起用。
- 掉落：脚下（中间和左右各 3）都没地就往下掉；摔超过 60 每 10 扣 1、最多 20；掉到底边或出了左右边就出局。
- 回合：每个角色出手一次算一回合，两队交替、队内按座位轮；第 30 回合打完按全队剩余血量定胜负。

## 数值（模拟器）

`npm run sim 100 ab`（电脑对电脑，0.1.0 平衡调整以后，2026-10-21）：

- 平均 **17.2 回合**一局（每人约 8–9 发）；命中率 43%；蓝队赢 56、黄队赢 43、平 1（种子 0–199 共 200 局是 102 比 97，差别是噪声）；
- 怎么结束：**掉出画本 44%**，血量掉光 48%，打满回合 7%，平局 1%；
- 道具使用率（每回合）：连发 +1 52%、连发 +2 17%、三岔 5%、加力 10% 6%、加力 20% 26%、加力 50% 52%、锅盖 22%、纸飞机 11%；
- 用和不用的胜率（全会的电脑对禁了这种道具的电脑，各 100 局，单双局换边）：连发 +1 51%、连发 +2 39%、三岔 42%、加力 55%、锅盖 47%、纸飞机 44%
  （禁掉一种，电脑就换别的道具顶上，单项大多在噪声范围里）；**全会对什么道具都不用：74%**（这组一局平均 20.4 回合）；
- 电脑想一手：中位 33 ms、最慢 88 ms（Node，不降速；`test/ai.test.ts` 卡 300 ms）。

0.1.0 平衡调整（DESIGN.md 2.6）的过程：

| 改了什么 | 一局几回合 | 掉出画本 | 蓝 : 黄 |
|---|---|---|---|
| 调整前（连发 70% / 55%，加力 50% 花 50，血量 100，挖坑半径 32） | 10.3 | 42% | 51 : 49 |
| 照设计改：连发 60% / 45%，加力 50% 花 60，血量 150；电脑的纸飞机条件放宽 | 11.7 | 63% | 55 : 45 |
| 再调挖坑半径和血量（60 局一组）：挖坑 30 / 28 / 26，血量 150 | 13.6 / 13.4 / 15.3 | 45% / 57% / 38% | — |
| 挖坑 26 + 血量 180 / 挖坑 27 + 血量 200 / 挖坑 25 + 血量 200 | 17.3 / 16.6 / 19.2 | 43% / 50% / 47% | — |
| **定下：挖坑半径 26、血量 180**（100 局） | **17.2** | **44%** | 56 : 43（200 局 102 : 97） |

血量从 100 涨到 150 以后，血量掉光变难，几乎都是被炸下画本结束，一局反而更短；所以挖坑半径从 32 降到 26（比伤害半径 30 还小），血量再加到 180。
挖坑半径仍然最敏感：差 1 就差一成多的掉出画本。

看得出的倾向：加力 50% 涨价以后还是每两手用一次；纸飞机现在约每 9 回合用一次（每人每局约一次）。

## 性能

- 远景整张、地形每 256×256 一块，都是烘焙好的画布，放在"镜头那一层"里按世界坐标摆好；镜头平移缩放只改这一层的 CSS transform（交给合成器），每帧不重贴；
  炸到哪块只重画哪块。上面一张透明画布每帧只画纸边、角色、炮弹、特效和名牌，JS 一帧约 1–2 ms。
- 画布渲染倍数封顶 2（手机按像素比 3 时也按 2 画）；远景按 0.4 倍烘焙。
- 实测（`npm run perf`，无头 Chrome、关 GPU 的软件渲染，手机横屏 844×390）：不降速时跟随、拖动、跟炮弹都是一帧 16.7 ms；
  CPU 降速 4 倍、像素比 3（画布按 2 画）时一帧约 50 ms（p95 约 67 ms），像素比 1.5 时约 33 ms，像素比 1 时中位 16.7 ms；
  每帧 JS 只花 1–2 ms，其余是软件合成整屏透明画布的时间（把上面那张画布或下面那一层任意藏掉一张，降速 4 倍也是 16.7 ms）。真机由 GPU 合成，还要在手机上实测确认。

## 部署

`wrangler.jsonc` 是独立配置（只有静态资源 `ASSETS`，没有 Durable Object，不写平台绑定和 `GATE`）：`npm run deploy` 能单独部署成一个游客就能玩的游戏。
本站部署时由维护者的部署工具补平台绑定、`GATE`、路由（见仓库根 docs/new-game.md 第 4、5 节）。还没有接平台的云存档和排行榜。
